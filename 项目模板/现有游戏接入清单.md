# 现有游戏接入清单

用于把已经存在的游戏工程纳入本资料库的管理，同时保留原工程与原远程仓库。

## 接入前检查
- [ ] 确认项目所有者及公开发布权限。
- [ ] 确认本地工程无未保存工作；先备份，再进行文件整理。
- [ ] 记录当前分支、远程地址、最近提交和工作区变更。
- [ ] 检查密钥、账号配置、个人数据、缓存、构建产物及第三方素材。
- [ ] 逐项确认素材授权；不确定授权的内容不上传公开仓库。
- [ ] 先将本资料库作为规范与索引，不直接替换原项目的 Git 远程地址。

## 推荐迁移方式
1. 保留原项目仓库及全部提交历史。
2. 在本资料库新增独立的项目说明目录，存放玩法概览、构建步骤、测试方法、资源授权清单和原仓库链接。
3. 源码需要集中管理时，优先使用独立仓库或 Git 子模块；只有确认历史、许可和文件范围后才考虑迁入本仓库。
4. 不把整个工作目录直接复制到公开仓库。
5. 从干净目录重新克隆，按说明安装依赖、导入引擎并实际运行，保留测试证据。

## 验收条件
- [ ] 原仓库仍可正常访问，提交历史未丢失。
- [ ] 公开内容经过敏感信息和授权检查。
- [ ] 新环境能够按说明恢复项目。
- [ ] 启动、核心玩法、胜负结算和目标平台构建均有真实测试结果。

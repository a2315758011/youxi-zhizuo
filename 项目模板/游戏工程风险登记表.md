# 游戏工程风险登记表

> 仅用于跨模块、多阶段、高不确定性或高影响项目。小型、明确、低风险任务不需要填写。

## 使用说明

- 风险不是已发生的缺陷；已发生的问题进入缺陷/故障记录。
- 每条风险必须有明确触发条件、责任人、下一步动作和复查日期。
- 概率与影响使用 1–5 分：1 极低/极小，5 极高/灾难性。
- 风险分值 = 概率 × 影响，仅用于排序；不得替代具体判断。
- 已接受的风险必须写明接受理由、有效期限和重新评估条件。

## 重点风险检查

- [ ] 引擎或插件版本兼容性是否已在真实目标版本验证
- [ ] 关键玩法系统是否存在单点故障或状态所有权不清
- [ ] 存档、内容 ID 或资源格式变更是否有备份和迁移回退
- [ ] 目标设备性能是否有真实采样，而非开发机推断
- [ ] 外部依赖、素材和服务是否有许可证、可用性或费用风险
- [ ] 构建、签名、发布或商店审核是否有不可逆门槛
- [ ] 关键任务是否有明确负责人、验收标准和可恢复断点

## 关闭条件

风险只有在触发条件消失、缓解措施经验证、项目范围不再包含该风险，或由明确责任人接受并设定复查日期后，才能关闭或转为“已接受”。不得因项目延期或暂时没有报错而自动关闭。

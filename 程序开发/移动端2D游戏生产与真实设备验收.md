# 移动端 2D 游戏生产与真实设备验收

## 适用范围

用于移动优先或 PC + 手机双平台的 2D 游戏。已有项目优先沿用当前引擎；Phaser + TypeScript + Vite 可作为移动浏览器/PWA 的候选默认路线，但不得仅因某份技能推荐它就迁移 Godot、Unity、Cocos 或其他现有工程。

## 一、先锁定游戏形态

开始资产生产前明确：
- 游戏类型与核心循环；
- 目标平台：PC、Android、iOS、移动浏览器/PWA；
- 输入方式：键鼠、手柄、触控；
- 画面方向、比例、目标分辨率和安全区；
- 资产是静态还是动态；
- 引擎、编辑器、SDK 与依赖的精确版本。

动态塔防、动作游戏中的植物、僵尸、敌人、Boss、NPC 默认属于动态单位；按钮、图标、背景、地图等通常是静态资产。若用户说“默认/自动”，按实际玩法推断并记录理由；如果资产制作任务中模式确实会改变交付结构且无法推断，只问一次“静态还是动态”。

## 二、按阶段交付

1. 需求与范围锁定：游戏简报、平台、输入、核心循环、胜负条件。
2. 玩法规格：规则、状态流、数值、敌人/单位行为与验收用例。
3. 性能预算：目标帧率、帧时间、纹理/内存预算、加载目标。
4. 可玩原型：先验证核心规则与输入，再扩大内容。
5. 资产母版：角色/单位先批准视觉母版，再扩展动作和变体。
6. 资源集成：登记资源 ID、引用、锚点、动画 key、压缩格式。
7. 浏览器/桌面测试：分辨率、窗口缩放、输入、暂停、重开。
8. 真实手机测试：触控、横竖屏、安全区、安装/更新、离线和恢复。
9. 发布证据：构建、测试、设备验证、版本标识、回滚方案。

## 三、动态对象必须有动画状态闭环

动态对象需建立状态映射表，至少记录：
- 逻辑状态；
- 触发条件；
- 代码状态/状态机；
- 动画 key；
- 对应帧序列或 clip；
- 动作结束后的回退状态；
- 中断规则（受击、死亡、暂停、场景切换）。

不能出现逻辑处于攻击状态但仍播放待机动画、动画结束后卡在无效状态、死亡对象继续攻击等断链。静态游戏不为形式强加 Sprite 动画。

## 四、真实设备与性能门禁

### 桌面
- 实际启动构建产物，不只运行开发服务器；
- 窗口缩放、键鼠/手柄、暂停恢复、重开、退出；
- 目标分辨率和低性能设备档位。

### 手机
- 至少一台目标 Android 真机；如声明 iOS 支持，还需相应设备或可信的设备测试证据；
- 点按、拖动、长按、双指操作（玩法需要时）；
- 横竖屏、刘海/圆角安全区、系统栏遮挡；
- 页面切后台/恢复、锁屏/解锁、断网/离线（适用时）；
- PWA 安装、更新和离线启动（仅 PWA 发行时）；
- 连续运行与热机后的帧时间、内存和资源释放。

模拟器/浏览器视口测试不能替代真机测试。没有设备时标记 NOT-RUN，不得宣称手机验收通过。

## 五、发布证据门禁

STAGING 仅证明结构、规则、资源清单和预算检查通过，不代表真实可玩或可发布。

SHIPPING 至少需要：
- 当前提交的测试命令真实 PASS；
- 当前提交的正式构建真实 PASS；
- 浏览器/桌面截图、视口与帧时间证据；
- 目标手机触控、方向、安全区和恢复测试证据；
- 资产运行时 QA 证据（存在动态资产时）；
- 版本号、构建产物哈希、已知问题、回滚步骤。

任何关键项缺失，状态保持 UNVERIFIED 或 BLOCKED，不得降级为普通警告。

## 六、遥测与隐私

默认关闭非必要遥测。确有崩溃分析或在线服务需求时，先说明收集字段、用途、保留期限和关闭方式；不采集与游戏质量无关的敏感数据。

## 七、完成定义

代码写完、开发服务器能打开、静态测试通过、单张截图正常，都不等于跨平台完成。只有目标平台构建、实际输入、真实设备、性能和发布证据达到对应门禁，才能声明支持该平台。

# 每日游戏制作技能搜集与维护规则

## 目标与唯一档案入口

- 唯一长期档案仓库：`a2315758011/youxi-zhizuo`，默认分支 `main`。
- 本规则只适用于游戏制作，不得将 AIGC 漫剧资料混入本仓库。
- 外部技能原文放入 `外部专业技能库/来源名/`；中文方法、调度和研究结论放在 `程序开发/`；每日研究日志放在 `测试验收/每日游戏技能搜集记录/`。

## 每日检索范围

持续覆盖：
1. 游戏策划、玩法循环、数值和平衡、关卡设计、游戏类型模板。
2. AI 编码规范、最小实现、根因调试、代码审查、测试驱动开发和反过度工程。
3. Unity、Godot、Unreal、Phaser、Cocos、Bevy、pygame、Defold、LÖVE、Roblox 等引擎及其精确版本适配。
4. 2D/3D 美术、资产规范、角色骨骼、动画、特效、音频、UI/UX、输入、物理和镜头。
5. 自动化测试、确定性回放、真人试玩、性能、跨平台、构建发布、存档迁移、长期维护、在线运营和故障恢复。
6. DeepSeek 生态中可复用的 SKILL.md、提示词、Agent 工作流与编码约束；同时调查其他主流 Agent Skills 生态，比较其实际增量。

## 候选评估门槛

每个候选必须记录：
- 原始仓库、作者、准确链接、分支/提交 SHA 或版本、最后更新时间。
- 许可证及再分发要求；缺少明确许可时不得复制原文。
- 实际阅读的 SKILL.md、必要 references/scripts；不能只看 README 或星数。
- 目标引擎/版本、依赖、命令、工具绑定、网络行为和潜在安全风险。
- 与本仓库现有技能的职责重叠、独特增量、适用任务和不采用原因。

分级：
- A：在具体用户游戏工程中完成可复现的对照测试并有证据。
- B：来源和内容已审阅，许可证/依赖明确，尚未在用户项目完成真实验证。
- C：候选或待核验，不得作为可直接执行的已验证技能。

## 去重与导入规则

- 先读 README、AGENTS、技能来源索引、既有来源 README 和历史研究日志，再检索和导入。
- 优先补充真正缺失的能力，不为增加数量导入重复内容。
- 已存在的上游来源只检查更新差异，不重复复制镜像或二次搬运。
- 先核对上游更新与本地差异，再决定是否更新；不得覆盖本地改写和用户修改。
- 导入时保留原始目录结构、LICENSE、NOTICE、版权声明及必要引用文件；避免只复制入口导致相对引用断链。
- 对工具专属流程、过重框架、与当前游戏无关的企业后端/云服务/微服务能力，优先登记不导入。
- 任何第三方脚本执行前先审阅其命令、依赖、文件和网络行为。
- 每个开发阶段最多调度 3 个专业技能加 1 个必要引擎技能；简单需求优先引擎原生能力和最小实现。

## 每日记录与质量门禁

每次记录检索日期、来源、候选数量、采用/拒绝/待核验原因、文件变更、许可证、上游 SHA、仓库提交 SHA、验证命令及真实输出、未验证事项和下一步。
- 若无合格新增，仍记录检索结果，不为凑数导入。
- 更新技能、索引、README 或 AGENTS 后，按仓库要求运行 `python tools/validate_game_repo.py`。
- 本地无法执行时标记“未执行/等待 CI”；不得把等待 CI 说成通过。
- 任何上游测试、静态检查或 AI 自评都不能冒充用户游戏的真实运行、设备测试或真人试玩。
- 汇报必须给出有依据的总进度百分比，并分别标记已完成、未验证和阻塞。

## 五、中文自动调度规则（强制）

1. 先识别当前游戏类型、引擎、版本、平台、当前阶段和具体问题。
2. 一次只为当前阶段选择最多 **3 个专业学科/类型技能 + 1 个必要引擎适配技能**。
3. 其余工作进入后续阶段，不要一次加载整个技能库。
4. 先读技能正文；只有正文明确引用且当前任务需要时才读参考文件或运行脚本。
5. 简单需求优先用引擎原生功能和最少代码；不为“显得专业”套用行为树、ECS、事件总线、框架或安全系统。
6. 只有玩法确实需要复杂决策时才用行为树/效用 AI；简单敌人优先有限状态机或几条条件判断。
7. 只有目标玩法需要多人/联网、交易、账号或玩家隐私时才加载网络安全、服务端权威、支付与隐私治理技能。
8. 每项技能默认标记 B 级（已导入、未在用户项目验证）；只有具体项目通过可复现测试才升 A 级。
9. 上游示例、技能文档、自动化检查均不能替代目标游戏真实运行和试玩证据。
10. 外部技能的命令、脚本、依赖和网络行为在执行前必须审阅；不盲目运行第三方代码。

## 六、按制作阶段选择

| 阶段/任务 | 首选技能（按需最多 3 项） |
|---|---|
| 立项与范围 | `game-planning`、`gameplay-design`、`prototype-fast` |
| 玩法规则与数值 | `gameplay-design`、`balance-design`、对应游戏类型技能 |
| 技术原型 | 对应引擎核心、`prototype-fast`、`game-feel` |
| 玩家/敌人控制 | 对应引擎移动、`game-ai`、必要时 `ai-behavior-trees-utility-ai` |
| 关卡 | `level-design`、`level-blockout`、必要时 `procedural-gen` |
| 场景与角色美术 | `create-game-assets`、`art-bible`、`ai-game-art-pipeline` |
| 动画 | `hd-sprite-sequence`、`pixel-animation` 或 `spine-skeletal`，按项目实际资产类型选 |
| UI/输入/音频 | 对应学科技能 + 对应引擎 UI/输入/音频适配 |
| 存档 | `save-systems`；有云同步才增加 `cloud-save`；有版本升级才增加 `save-integrity` |
| 测试试玩 | `game-qa`、`gameplay-validation`；需要回放驱动才加 `gameplay-harness` |
| 性能 | `performance-budget` + `performance-optimization` |
| 发布 | `ship-checklist` + 目标平台/商店发布技能 |
| 长期运营 | `live-ops`；只有在线活动/远程配置才启用 |

## 采用内容

- 从玩家体验反推支柱、功能、任务和迭代。
- 区分玩家可感知功能与跨功能支撑能力。
- 用 L1-L4 描述单项功能的证据成熟度。
- 每轮迭代产出可试玩或可检查的成果，并定义回滚条件。
- 识别各核心支柱成熟度失衡，避免局部过度打磨。

## 本仓库的改写与边界

- 以中文重新组织并适配本仓库既有工作流。
- 明确 L1-L4 仅描述单项功能证据成熟度，不能替代项目总进度百分比。
- 明确本技能不替代 Project Orchestrator、资源锁、规则门禁、自动化测试和真实试玩。
- 简单项目可以合并支柱，不强制增加层级或任务系统。
- 不导入上游两个 Python 热力图脚本、3D Three.js 可视化器及 vendor 依赖：它们不是规划方法的必要组成；本仓库已有任务台账和进度证据体系，避免为可视化增加约 600 KB 第三方运行时代码及额外维护负担。
- 上游 README 声明该项目是轻量 PM scaffold，不是生产级项目管理平台；本仓库不把它描述为完整项目管理软件。

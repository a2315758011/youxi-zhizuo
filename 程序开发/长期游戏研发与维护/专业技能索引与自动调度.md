# 专业游戏开发技能索引与自动调度

本索引负责把已导入的技能库路由到当前任务。**技能多不代表每次都要全部加载。**

## 一、任务入口

1. 恢复项目事实：路径、引擎与精确版本、分支、提交、工作区、运行状态和未完成任务。
2. 识别当前阶段、游戏类型、目标平台和用户已确认的决策。
3. 优先读取 [专业游戏技能库来源与中文调度索引](../专业游戏技能库来源与中文调度索引.md)。
4. 每个阶段最多选 3 个专业技能 + 1 个必要引擎技能；其余任务延后到对应阶段。
5. 先复用引擎原生能力和已有代码；任何新增复杂度必须通过 [AI 简洁性约束](../从零制作游戏全流程与AI简洁性约束.md)。
6. 技能默认 B 级（已导入、未在用户项目验证），实际项目测试通过才升级为 A 级。

## 二、已找回的主要技能来源

- `awesome-gamedev-agent-skills`：77 项跨引擎技能，包含 15 项通用学科、9 种游戏类型、4 项生产工作流和 49 项引擎技能；另保存技能路由、兼容文档、许可证和 24 份通用参考资料。
- `open-game-skills`：24 项精选技能，补足精灵动画、角色骨骼、资产管理、玩法试玩、QA、测试矩阵、性能预算、存档和长期运营。
- `ai-game-art-pipeline`：游戏运行时美术流水线，包含资产生成、透明处理、帧提取、精灵联系表和运行时交付参考。

具体文件、中文说明和路径见 [专业游戏技能库来源与中文调度索引](../专业游戏技能库来源与中文调度索引.md)。

## 三、按任务自动选择

| 当前任务 | 最小技能组合示例 |
|---|---|
| 新游戏立项 | game-planning + gameplay-design + prototype-fast |
| 玩法原型 | 对应引擎核心 + gameplay-design + prototype-fast |
| 简单敌人 | game-ai（优先 FSM/条件判断）+ 对应引擎脚本 |
| 复杂敌人决策 | game-ai + ai-behavior-trees-utility-ai + 对应引擎 |
| 关卡 | level-design + level-blockout；确有随机生成再加 procedural-gen |
| 资产制作 | create-game-assets + art-bible + ai-game-art-pipeline |
| 角色动画 | hd-sprite-sequence + pixel-animation 或 spine-skeletal；按资产类型选其一 |
| UI/输入/音频 | 当前需要的一个学科技能 + 必要引擎适配 |
| 存档 | save-systems；需要云同步才加 cloud-save |
| QA/试玩 | game-qa + gameplay-validation；需要自动回放才加 gameplay-harness |
| 性能 | performance-budget + performance-optimization |
| 长期运营 | live-ops；只有在线活动/远程配置时启用 |
| 发布 | ship-checklist + 目标平台发布技能 |

这些是选择示例，不是要求每次同时加载整行所有技能。

## 四、引擎专属路由

- Cocos Creator：按项目锁定版本读取 Cocos 技能；验证微信/抖音目标构建、生命周期、输入和资源加载。
- Godot：根据 project.godot 和版本选择 GDScript/C#、节点、动画、物理、UI、导出与无头测试技能。
- Unity：根据 ProjectVersion.txt 与依赖锁选择 C#、输入、动画、物理、Tilemap 和构建技能。
- Unreal：根据 .uproject 版本选择蓝图/C++、行为树、输入、Niagara 和打包技能。
- Phaser/Web：根据 package.json 与锁文件选择 Phaser、PixiJS 或 three.js 对应技能。
- Bevy、Defold、LÖVE、pygame、Roblox、Ebitengine：只在项目实际采用该引擎时调用对应技能。

已有项目优先沿用当前引擎；不得因为技能库中某引擎技能较多就迁移项目。

## 五、复杂度与安全边界

- 简单玩法优先少量函数、引擎原生节点和清晰状态；不默认引入 ECS、行为树、事件总线、插件系统。
- 离线单机游戏不加载网络、账号、支付、反作弊或服务端权限技能。
- 只有目标玩法需要联网、交易、账号、云同步或隐私数据时才加载对应安全技能。
- 每个新增依赖、模块、服务和安全层必须说明真实需求、风险、最简单替代方案及测试方法。
- 外部脚本执行前审阅源代码和依赖，不自动执行未知安装命令。

## 六、验证等级

- A：在用户真实项目、锁定引擎版本和目标平台通过测试。
- B：技能已导入并回读，尚未在用户项目验证。
- C：候选资源，需先审查和小型探针。
- D：不适用、过时或不满足许可/兼容要求。

不得仅凭 GitHub 星数、上游 README 或技能文件存在就评为 A。


## 五、真实质量与技能效益

- 移动端/双平台：读取 [移动端 2D 游戏生产与真实设备验收](../移动端2D游戏生产与真实设备验收.md)。
- 角色、植物、敌人和动态单位资产：读取 [2D 美术资产与运行时交付规范](../2D美术资产与运行时交付规范.md)。
- 技能选型、对照和淘汰：读取 [游戏技能效果评估与对照测试规范](../游戏技能效果评估与对照测试规范.md)。
- 不因技能数量增加而提高质量评级；以同一任务的基线组/技能组、实际测试结果、缺陷和复杂度成本为依据。

- 玩法系统与回归测试：按需读取 ForgeSkills 的 `gamedev-gameplay-systems`、`gamedev-game-testing`。
- 最终交付声明：读取 ForgeSkills 的 `gamedev-verification`，必须记录未验证项。
- 参考图视觉反复修改未收敛：按需读取 `gamedev-visual-iteration`，固定视角、量化差异、一次只修一个主因。
- 详细边界见 [ForgeSkills 质量验证与视觉迭代调度](../ForgeSkills质量验证与视觉迭代调度.md)。

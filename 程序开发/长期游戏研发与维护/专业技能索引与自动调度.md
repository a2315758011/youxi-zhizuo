# 专业游戏开发技能索引与自动调度

本索引把仓库规则与当前可调用的专业 Skill（技能）连接起来。技能存在不代表已在目标项目执行，也不代表相关软件已安装。

## 一、任务入口

所有游戏任务先执行：

1. 恢复项目事实：项目路径、引擎与版本、分支、提交、工作区、运行状态、未完成任务。
2. 识别主引擎：只选一个主引擎，读取项目锁定版本；已有工程不得无证据迁移。
3. 分类任务：策划/玩法、程序、AI、关卡、美术、动画、UI、输入、音频、存档、网络、性能、测试、发布、线上维护。
4. 只加载当前任务所需的最小技能集合。
5. 先复用成熟上游项目、现有工具和已有模块；自研必须说明现有方案为什么不满足。
6. 建立变更、测试、证据、回滚闭环。

| 技能方向 | 可调用技能 | 典型触发任务 |

## 三、引擎专属路由

- Cocos Creator：先核实工程版本与目标平台；使用项目已安装的编辑器、官方开发者工具和对应 API，不得把 Phaser/Godot 方案直接套入。
- Godot：按 project.godot 与版本锁定，选择 GDScript/C#、场景、资源、动画、物理、UI、导出及 headless 测试技能。
- Unity：按 ProjectSettings/ProjectVersion.txt 与依赖锁定，选择 C#、输入、动画、资源数据、物理和构建技能。
- Unreal：按 .uproject 与引擎版本选择蓝图/C++、输入、AI、Niagara 和打包技能。
- Phaser/Web：按 package.json 与锁文件确认 Phaser 版本，选择渲染、输入、性能、浏览器测试和 Web 发布技能。
- Roblox：按 place/Rojo 项目结构选择 Studio 工作流、Luau、网络安全、数据存储和 UI 技能。

不能识别引擎时，先检查工程文件；只有引擎选择确实影响实现且无法推断时，才询问用户。

## 四、长期维护专用调度规则

### 新功能/持续迭代
项目恢复 → 范围与验收锁定 → 架构影响分析 → 任务拆分 → 实施 → 自动测试 → 真实运行 → 回归 → 版本记录。

### 存档/玩家数据
save-systems → 引擎存储 API → 旧版本样本迁移测试 → 崩溃中断测试 → 备份恢复演练。

### 性能下降
performance-optimization → 引擎 Profiler → 固定场景/设备采样 → CPU/GPU/内存归因 → 单点优化 → 同条件复测。

### 内容扩充
create-game-assets/美术总管 → 资产 ID 与许可登记 → 导入/压缩 → 引用完整性 → 运行时视觉 QA → 包体预算。

### 正式发布
引擎构建技能 → 发布门禁 → 干净环境安装 → 升级与旧存档测试 → 版本证据 → 回滚点 → 发布后监控。

### 线上故障
故障分级 → 保全日志/构建/数据 → 止损或回滚 → 复现 → 根因修复 → 回归 → 复盘。

## 五、技能采用等级

- A 级：已有实际项目/测试证据，已验证可用。
- B 级：有明确技能说明和可复现方法，但尚未在用户目标项目验证。
- C 级：候选工具/方法，需先做小型探针。
- D 级：不适用、已过时或存在许可/兼容风险，暂不采用。

每个技能登记引擎版本、适用平台、依赖、许可、输入输出、验收方法、最近验证日期和失败替代方案。不得仅因技能名称存在就评为 A 级。

## 六、当前可用专业技能的边界

当前会话可调用的专业技能包含跨引擎玩法、AI、关卡、存档、性能、UI、输入、音频、资产、Godot/Unity/Unreal/Phaser 等引擎方向，以及 2D 手机游戏制作和美术总管。它们可辅助制定方法和执行具体任务；是否适合某项目，必须先识别项目引擎和版本。

本仓库维护长期通用规范、索引和模板；不把某个会话的内部工具描述误写成已安装到用户电脑的软件，也不复制整个上游技能仓库。

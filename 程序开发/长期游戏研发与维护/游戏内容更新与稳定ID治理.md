# 游戏内容更新与稳定 ID 治理

> 适用：会持续增加关卡、敌人、道具、角色、任务、剧情或活动内容的游戏。
> 小型一次性小游戏不需要复杂内容包系统，只落实稳定 ID、版本记录和引用检查即可。

## 一、区分四种身份

| 类型 | 示例 | 是否允许随意改变 |
|---|---|---|
| 稳定内容 ID | enemy_slime_001、level_forest_02 | 不允许；发布后视为数据契约 |
| 显示名称 | 绿色史莱姆、森林第二关 | 可以改名、多语言 |
| 文件路径 | res://art/slime.png | 可迁移，但需更新引用 |
| 内容版本 | content_schema=3、pack=1.4.0 | 按兼容规则递增 |

不要用显示名称、文件名、数组序号或场景节点路径作为存档中的唯一身份。

## 二、内容清单（Manifest）

内容规模达到需要清单时，为每类内容建立一份机器可读 manifest。每个条目最少记录：
- 稳定 ID；
- 内容类型；
- 数据 schema 版本；
- 资源/数据引用；
- 状态：active / deprecated / removed；
- 引入版本；
- 依赖的其他稳定 ID；
- 许可和来源（涉及第三方资产时）。

清单校验至少检查：
- ID 唯一；
- 引用目标存在；
- 依赖没有循环或缺失；
- 关卡入口与出口存在；
- 关键任务/奖励引用有效；
- 已发布 ID 不被无记录地复用；
- 资源引用可导入、可加载。

小项目可先用一份 JSON/YAML/CSV 或引擎原生资源清单，不要为了形式增加数据库或服务。

## 三、发布后的 ID 规则

- 已发布 ID 永不分配给另一种内容。
- 改名只改显示字段，不改 ID。
- 删除内容前先判断旧存档、旧关卡、任务、成就或回放是否仍引用。
- 必须替换时建立明确 alias/mapping：old_id → new_id，说明转换规则。
- 无法合理替换的旧内容标记 deprecated，保留最小兼容数据。
- 不要通过相似名称、模糊匹配或资源路径猜测旧 ID。

## 四、内容与存档兼容

玩家存档引用稳定 ID，而不是内容数组下标。每次内容更新要验证：
1. 旧存档中引用的 ID 仍存在或有迁移映射；
2. 被移除的道具/敌人/任务有确定处理策略；
3. 关卡重排不改变玩家已解锁内容的身份；
4. 旧任务标记不会错误映射到新任务；
5. 随机地图、掉落或遭遇使用固定种子与版本化生成规则；
6. 旧版本回放不会因为内容表顺序变化而被静默改写。

若程序化生成算法改变，必须记录 generator_version；只保存 seed 而不保存生成规则版本，不能保证长期重现。

## 五、内容包与版本兼容（按需启用）

当游戏确实有可独立更新的内容包、DLC、活动或远程配置时，内容包至少声明：
- pack_id / pack_version；
- schema_version；
- minimum_client_version；
- 依赖的基础内容版本；
- 激活与过期时间（仅限定时内容）；
- 缺失/过期时的基础回退；
- 回滚到上一兼容包的方式。

加载内容包前先校验兼容性和所有必需引用。未知必需字段、缺少必需资源或不兼容客户端时，回退到已发布的基础内容，不要半加载状态继续运行。

纯单机游戏若所有内容随客户端一起发布，不必为了它引入远程配置、在线活动服务或热更新服务器。

## 六、内容修改的最小回归

每次内容变更按影响范围选择：
- 道具/装备：获取、使用、消耗、升级、出售、旧存档引用；
- 敌人：生成、AI 状态、受击、死亡、掉落、关卡引用；
- 关卡：入口、出口、路径可达、胜负、存档恢复；
- 任务/剧情：触发条件、前置依赖、奖励、旧任务标记；
- 资产：导入、尺寸、透明度、动画帧、运行时引用和包体；
- 随机生成：固定种子重放、生成合法性、边界条件和版本差异。

不能只检查新内容能显示，还要验证旧内容和旧存档没有被破坏。

## 七、内容更新发布流程

1. 记录本次新增、修改、废弃和删除的稳定 ID；
2. 检查 manifest、依赖、引用、许可证；
3. 运行受影响内容的规则/数据测试；
4. 用代表性旧存档检查兼容；
5. 在真实游戏中进入、使用、完成对应内容；
6. 记录截图/日志/回放与构建版本；
7. 生成内容变更说明；
8. 保留上一份兼容内容清单和回滚策略。

## 八、AI 简洁性限制

- 先用稳定 ID 和版本字段解决真实兼容问题，不默认创建大型内容管理平台。
- 不因未来可能有 DLC 就提前建设在线内容分发。
- 不把每个图标、粒子、临时 UI 元素都做成复杂内容注册系统。
- 没有跨项目复用证据时，优先保持项目内简单数据结构。
- 内容自动生成必须经过规则校验和真实关卡可达性检查，不能把“生成成功”当作“关卡可玩”。

# 直播炮塔守城：程序技能 A/B 对照实验执行单

> 状态：准备中 / 本地工程连接阻塞。本文是预注册实验方案，不是已执行的游戏测试报告。

## 1. 实验目标

验证新增的“游戏程序开发与代码最小化”及“玩法系统实现与可玩闭环”是否能在真实游戏工程中：
- 提高需求实现正确率与关键玩法回归通过率；
- 减少无必要文件、代码、依赖、抽象和状态；
- 避免破坏已有玩法、存档、平台适配与资源引用；
- 让 AI 的完成声明与真实运行证据一致。

本实验不以代码行数越少越好为目标，也不以文档数量或 AI 自评分数作为结论。

## 3. A/B 组定义

### A 组：基础工作流

- 使用项目现有 AGENTS.md、README、既有测试和引擎官方文档。
- 不加载本轮新增的两项技能。
- 不得故意跳过项目约定、历史行为或现有测试。
- 必须执行同样的需求确认、代码侦察和验收步骤。

### B 组：新增技能工作流

- 使用相同项目规则、需求、代码基线和工具权限。
- 加载“游戏程序开发与代码最小化”。
- 玩法逻辑任务再加载“玩法系统实现与可玩闭环”。
- 不允许额外获得 A 组没有的需求信息。

### 重复次数

每组至少 3 次。每次使用隔离 worktree、临时分支或完整恢复点；不得让前一轮残留改动污染后一轮。若工具或工程无法安全隔离，暂停实验，不在同一工作区连续覆盖。

## 4. 任务选择规则

实验任务必须从实时源码审计后选择，满足：
- 功能范围小、验收条件可观察；
- 不涉及未授权设备或其他执行者持锁的文件；
- 能在当前引擎版本和现有测试入口中复现；
- 有明确的现状基线与相邻回归。

优先从以下候选类型中选一个实际存在且安全的任务：
1. 一个明确的 UI/输入边界行为；
2. 一个有复现步骤的小型玩法状态缺陷；
3. 一个重复逻辑的小范围合并（必须保持外部行为不变）。

不得仅因任务名称好看而假设该功能缺失。先查源码、测试和近期缺陷，再登记最终任务 ID 与验收条件。

## 6. 记录指标

### 正确性与质量
- 验收条目通过数 / 总数；
- 新增缺陷、修复缺陷、回归失败数；
- 是否先复现、定位根因，再实施修复；
- 关键状态、重复输入、暂停、胜负、重开行为；
- 构建和真实引擎运行结果。

### 复杂度成本
- 新增/修改文件数；
- 新增代码行数（只作诊断，不作为单独排名）；
- 新增依赖、服务、定时器、状态和配置；
- 新增抽象及其真实使用点；
- 实现耗时、排错耗时、回归耗时；
- 是否重复实现已有组件或引擎能力。

### 证据等级
- E0：未执行；
- E1：静态审阅；
- E2：工具/自动化测试实际运行；
- E3：Cocos Creator 真实构建、场景运行和关键玩法通过；
- E4：真实目标设备或真人试玩通过。

## 7. 一票否决项

任一组出现以下情况，该轮不得判定成功：
- 无法启动或关键场景崩溃；
- 核心玩法错误、无法完成一局或无法重开；
- 玩家数据/存档丢失或被覆盖；
- 关键触控/输入失效；
- 破坏现有平台构建或既有回归；
- 未经许可修改其他执行者持锁文件；
- 把未运行测试写成通过。

## 9. 结论门槛

- B 组必须在关键正确性上不低于 A 组，且不得触发一票否决。
- B 组若明显减少无必要复杂度或排错/回归成本，并保持相同或更高正确性，才支持保留新增技能。
- 若 B 组增加复杂度却没有可重复收益，应精简技能或改为条件加载。
- 只有完成至少 3 轮且证据达到 E3，才可讨论升级为 A 级；需要玩家体验结论时还必须达到 E4。
- 结果不显著或样本不足时，结论为“尚无充分证据”，不得强行宣布 B 组更优。

### 工具使用边界

1. 优先使用项目当前编辑器、内置预览、开发者工具和已有自动化测试；先核实工程现成测试入口，不为实验另装大型测试框架。
2. Cocos Creator 2.x 与 3.x API 并非完全兼容，代码建议必须锁定项目实际版本。
3. Cocos Store 的 Runtime Inspector + MCP 商品页面建议 3.8.8；这不能证明兼容历史 3.8.2。本实验不安装、不依赖该插件，除非先完成精确版本兼容和许可核验。
4. A/B 两组必须使用同一调试入口、构建目标和日志采集方式。
5. 运行截图、控制台日志、构建结果与测试报告绑定同一代码提交和构建编号。

### 当前研究结论

官方资料支持使用 Cocos Creator 自带预览/调试能力与版本对应手册开展验证；尚未证明当前游戏工程能无误构建，也没有新的本地运行证据。本节不提升技能等级。

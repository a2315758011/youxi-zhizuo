## 已保存技能

| 中文目录 | 上游路径 | 适用场景 |
|---|---|---|
| 游戏玩法架构 | skills/engineering-common/gameplay-architecture | 跨模块玩法系统设计、状态所有权、事件流和更新顺序 |
| 崩溃分诊 | skills/qa-release/crash-triage | 崩溃聚类、符号/构建信息核验、复现与发布影响判断 |
| 工程风险登记 | skills/workflow/risk-register | 里程碑风险、技术未知项、触发条件、缓解与回退方案 |

## 为什么只选这三项

- 游戏玩法架构：比通用代码架构审查更贴近玩法系统，但与现有总规范部分重叠，因此只在跨系统设计时按需读取，不重复建立新架构框架。
- 崩溃分诊：补充专门的崩溃签名聚类、符号质量和发布影响判断；与通用根因调试互补，不替代复现和根因修复。
- 工程风险登记：补充风险责任人、触发条件、缓解措施和回退路径；只用于多阶段项目或高风险里程碑，不要求每个小任务都填表。

## 明确不导入

- QA Test Matrix：与本仓库已有 game-qa、测试矩阵和真实游戏验收规范重叠。
- Playtest Analysis：与玩家体验与游戏平衡评估、玩家试玩记录表重叠。
- Verification Loop：与完成前证据验证、全链路回归扫描重叠。
- Continuous Learning：与工程约束固化及既有长期维护流程重叠。
- AI 资产生成脚本和付费 API：不作为本仓库依赖；用户要求免费优先。
- 上游完整 Agent/命令/Hook/适配器框架：体量和运行依赖过大，当前项目没有证明其必要性。

## 使用边界

- 三项技能均为“已导入、待真实项目验证”，默认 B 级。
- 先遵循本仓库 AGENTS.md 和 AI 游戏代码工程总规范，再按任务读取单项技能。
- 不安装上游 npm 依赖，不执行其脚本，不复制其 Agent/Hooks/配置覆盖现有规则。
- 发生崩溃时先保留原始日志、构建版本、符号和复现线索，再分诊；不得仅凭相似堆栈就认定同一根因。
- 风险登记必须记录触发条件和下一步动作；没有实际风险的简单任务不创建登记表。

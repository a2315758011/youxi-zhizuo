## 采用边界

- brainstorming 适合新功能/玩法设计；小型明确修复不强制进行完整构思仪式。
- TDD 优先用于可确定的逻辑和缺陷；纯美术导入、文档或不可自动断言的视觉任务使用基线截图、验收清单和运行验证，不伪造单元测试。
- 系统化调试与本仓库的系统化缺陷修复技能互补：先用可复现证据定位，避免两个流程重复执行。
- 完成前证据验证是所有任务的发布声明门禁。
- 上游部分技能假定存在子代理或工作区能力；本仓库不默认拥有这些能力。没有真实独立审查者时，不得把单模型自审标记为独立代码审查。
- 原始资料等级：已导入、来源和许可已记录；尚未在具体游戏项目完成对照验证。
